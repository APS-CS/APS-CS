### 🔧 What I do

- **Governance & compliance:** Information security management, ISO/IEC 27001, NIS2, GDPR, security policy and documentation, risk assessment, supplier and third-party assessment.
- **AI governance:** EU AI Act transparency obligations, data classification for AI tooling, vendor assessment under GDPR and CLOUD Act exposure.
- **Defensive security & infrastructure:** OPNsense, Suricata IDS/IPS, VLAN segmentation, firewall rules, WireGuard, Linux and Docker hardening.
- **Offensive security:** Primarily web application testing with Burp Suite and tools in Kali Linux, findings reporting and remediation advice.
- **Analysis & scripting:** Wireshark, Python, PowerShell and Bash.

### 🧭 Security frameworks in practice

Framework references connect the practical work to the security requirements and priorities organisations work with. The aim is to explain how a project decision relates to a recognised security practice and what evidence supports that connection.

| Framework or standard | Application in the portfolio |
| :--- | :--- |
| **MITRE ATT&CK & D3FEND** | Relevant attacker behaviours and defensive techniques, particularly in network segmentation, infrastructure hardening and security testing. |
| **ISO/IEC 27001 & 27002** | Information security governance, risk-based decisions and security measures such as access control and cryptography. |
| **CIS Controls v8.1** | Practical measures for secure configuration, data protection, access management, network defence and penetration testing. |
| **NIST CSF 2.0** | Relating project activities to Govern, Identify, Protect, Detect, Respond and Recover, according to each project's scope. |
| **OWASP WSTG & ASVS** | Web security test methods and application security requirements. WSTG is already used in the website assessment; ASVS provides a reference for further requirements mapping. |
| **ISO/IEC 27035 & NIST SP 800-61 Rev. 3** | References for developing incident management documentation, including preparation, assessment, response and lessons learned. |
| **CIS Benchmarks** | Product-specific references for developing the Windows hardening guide. Detailed mapping requires a selected benchmark version and documented configuration checks. |

Connections are limited to what the project documentation supports. A relevant reference does not mean that every requirement has been implemented or tested, and planned work is not presented as completed coverage.
